# V1 Deployment Guide

Detailed setup and browser access for the [project README](../README.md). Run all commands from the repository root inside the playground.

## Setup inside the lab environment

These commands run **in the playground terminal**, not on a local Kubernetes cluster. Changes must first be transferred there: after an approved commit/push, clone the repository; until then upload the modified project files through your supported transfer method. A clone of the current remote will not contain unpushed files.

```bash
git clone https://github.com/ThinkWithOps/thinkwithops-openwebui-production.git
cd thinkwithops-openwebui-production
mkdir -p _local
python3 -m venv _local/venv
source _local/venv/bin/activate
python3 -m pip install -r scripts/requirements-validation.txt

# If Helm is missing, install the same pinned version used in CI.
curl -fsSL https://get.helm.sh/helm-v3.19.0-linux-amd64.tar.gz -o _local/helm.tar.gz
curl -fsSL https://get.helm.sh/helm-v3.19.0-linux-amd64.tar.gz.sha256sum -o _local/helm.sha256sum
(cd _local && cp helm.tar.gz helm-v3.19.0-linux-amd64.tar.gz && sha256sum -c helm.sha256sum)
tar -xzf _local/helm.tar.gz -C _local
export PATH="$PWD/_local/linux-amd64:$PATH"

kubectl config current-context
# Inspect that output before setting this. Never point at an unrelated cluster.
export EXPECTED_CONTEXT='REPLACE_WITH_PLAYGROUND_CONTEXT'
export SESSION_EXPIRES_AT='REPLACE_WITH_ACTUAL_EXPIRY_AND_TIMEZONE'
export PLAYGROUND_ACCESS_METHOD='Playground View Port on 30080'
kubectl get storageclass
export STORAGE_CLASS='REPLACE_WITH_VERIFIED_CLASS'
bash scripts/preflight.sh > _local/preflight.txt 2>&1
cat _local/preflight.txt
```

Preflight must exit zero. Review node allocations, quotas, available disk, controller state, and time remaining. If no storage class exists, complete [storage setup](storage.md), then rerun preflight. The scripts do not install an ingress controller, storage operator or cloud resources.

For ARM nodes, obtain the matching Helm CLI archive; container runtime architecture/pull access remains part of live checks.

```bash
# Obtain the HTTPS View Port URL as described below. Do not share API keys in chat.
python3 scripts/configure-playground.py
export PREFLIGHT_REVIEWED=yes
bash scripts/deploy.sh
bash scripts/verify.sh
bash scripts/export-artifacts.sh
```

Configuration prompts for endpoint, model ID, StorageClass, browser URL, bootstrap admin and API key. Generated DB/Redis/signing credentials are written to ignored `_local/secrets.json` with mode 0600 and sent to Kubernetes over stdin. Re-running preserves the existing Secret and signing key. The bootstrap admin exists before public access; self-signup is disabled. Store credentials securely outside the session.

One configured endpoint does not enforce an API billing/model allowlist. `DEFAULT_MODELS` chooses the default; enforce permitted models with provider credentials or Open WebUI model access controls. Real smoke tests call the model and may incur provider charges.

An existing Secret is never silently rotated. Updating private credentials requires a deliberate Secret update and app restart; changing a PostgreSQL password also requires a coordinated database-role change. Do not regenerate it against an existing PVC.

## Browser access

### Default: Playground View Port

The chart exposes NodePort **30080**. In the playground UI select **View Port → 30080**. Use the **exact HTTPS URL generated by that session** as `WEBUI_URL` when configuring. The URL cannot be known before your session exists; record it privately in `_local/access.txt`. No public URL has been verified here.

If View Port lands on a student/jump node outside the cluster, forward from that node to a reachable Kubernetes node:

```bash
# Run on the View Port entry node; substitute the reachable node hostname/IP.
# socat must already be installed or installed through the playground's package manager.
socat TCP-LISTEN:30080,reuseaddr,fork TCP:REPLACE_REACHABLE_K8S_NODE:30080
```

Keep that terminal open. If `kubectl` is configured on the entry node, an alternative is:

```bash
kubectl -n thinkwithops-openwebui port-forward --address=0.0.0.0 service/openwebui 30080:80
```

Binding `0.0.0.0` exposes that listener on the playground network. Use it only on the intended lab entry node behind the supported access proxy. A port-forward must be restarted after the application pod is replaced.

The browser leg uses the platform's TLS proxy; NodePort/backend traffic remains HTTP. Verify the certificate and streaming/WebSocket behavior in your actual session. No self-managed end-to-end TLS or permanent hostname is claimed. If the platform provides only plain HTTP or does not forward WebSockets, stop and use a verified TLS ingress path.

### Existing ingress + TLS

Use `kubectl get ingressclass` plus controller pod inspection. Reuse only a running controller that supports WebSockets. Supply a hostname resolving to that controller and a valid TLS Secret in `thinkwithops-openwebui`; no ACM assumption is made.

```bash
cp helm-chart/values-ingress.example.yaml _local/values-ingress.yaml
# Edit class, host and WEBUI_URL; add controller-specific timeout/WebSocket settings.
kubectl -n thinkwithops-openwebui create secret tls openwebui-tls \
  --cert=/private/path/tls.crt --key=/private/path/tls.key
export INGRESS_VALUES="$PWD/_local/values-ingress.yaml"
bash scripts/deploy.sh
```

Exact URL is `https://<configured ingress host>`. Keep `WEBUI_URL` and the browser hostname identical. Neither TLS path is verified until browser checks pass.
